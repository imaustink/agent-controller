━━━ Summary
NAME         PHASE       JOB                  BACKEND   AGE
on-job       Succeeded   toolrun-on-job       job       50s
on-sandbox   Succeeded   toolrun-on-sandbox   sandbox   42s

  What this proves
    • The ToolRun CRD is unchanged as a public API; only the workload kind differs.
    • ADR 0010's rule holds: the workload's own status, not the callback, decides
      the terminal phase — via the Sandbox Finished condition.
    • docs/security.md's hardened contract is byte-identical across backends.
    • Credentials stay secretKeyRef-resolved; nothing is written in plaintext.
    • Suspend/resume is declarative state, and the pod keeps its name and
      hostname across the cycle. (A Job can suspend too — spec.suspend — but
      a resumed Job gets a brand-new pod with a new random name.)
    • ownerReferences GC is preserved.

  What this does NOT prove
    • Resume is a cold restart on retained volumes. Mid-process wake needs GKE
      Pod Snapshots (GKE Standard ≥1.35.3, gVisor node pool, GCS bucket).
    • Nothing about isolation. Neither backend sets runtimeClassName, and kind
      runs stock runc. Note that runtimeClassName is a plain PodSpec field, so
      gVisor is available on the Job path too — it is not a reason to adopt this.
    • AgentRun still runs on Jobs; only ToolRun has the backend switch.
